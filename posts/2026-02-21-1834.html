Topos Theory: Categorical Logic and Geometry

topos-theory

Motivation

Topos theory, developed by Grothendieck and refined by Lawvere and Tierney, provides a categorical framework that unifies geometry and logic. A topos can be viewed as a generalized topological space or as a universe of sets where intuitionistic logic holds. This dual nature makes topoi powerful tools for studying geometric objects through their internal logic and for constructing models of set theory. Applications range from algebraic geometry (étale cohomology) to logic (forcing in set theory) to theoretical computer science (type theories and realizability). The theory reveals deep connections between continuity, constructivity, and the foundations of mathematics.

Definitions

  • Category: A collection of objects and morphisms with composition and identities satisfying associativity and unit laws.
  • Functor: A structure-preserving map between categories, assigning objects to objects and morphisms to morphisms.
  • Natural Transformation: A morphism between functors: for functors \(F, G: \\mathcal{C} \\to \\mathcal{D}\), a family of morphisms \\(\\alpha_X: F(X) \\to G(X)\\) satisfying naturality.
  • Limit: A universal cone over a diagram. Examples: products, equalizers, pullbacks.
  • Presheaf: A functor \\(P: \\mathcal{C}^{op} \\to \\mathbf{Set}\\). The category of presheaves is \\(PSh(\\mathcal{C}) = [\\mathcal{C}^{op}, \\mathbf{Set}]\\).
  • Sheaf: A presheaf satisfying a gluing condition: compatible local data can be uniquely glued to global data.
  • Grothendieck Topology: A structure on a category specifying which families of morphisms are "covering families."
  • Topos: A category equivalent to the category of sheaves on a site (Grothendieck topos) or satisfying Giraud's axioms.
  • Subobject Classifier: An object \\(\\Omega\\) classifying subobjects: monomorphisms \\(A \\hookrightarrow B\\) correspond to morphisms \\(B \\to \\Omega\\).

Theorem: The Fundamental Theorem of Topos Theory

Theorem: For any topos \\(\\mathcal{E}\\) and any object \\(X \\in \\mathcal{E}\\), the slice category \\(\\mathcal{E}/X\\) is a topos. Moreover, the pullback functor \\(X^*: \\mathcal{E} \\to \\mathcal{E}/X\\) has both left and right adjoints (\\(\\Sigma_X \\dashv X^* \\dashv \\Pi_X\\)).

Proof: We verify Giraud's axioms for \\(\\mathcal{E}/X\\). Since \\(\\mathcal{E}\\) is a topos, it has all finite limits. The slice category \\(\\mathcal{E}/X\\) inherits finite limits computed pointwise over \\(X\\). Colimits in \\(\\mathcal{E}/X\\) are computed by taking colimits in \\(\\mathcal{E}\\) and then mapping to \\(X\\).

The subobject classifier in \\(\\mathcal{E}/X\\) is \\(\\pi_2: X \\times \\Omega \\to X\\) where \\(\\Omega\\) is the subobject classifier in \\(\\mathcal{E}\\). For an object \\(f: Y \\to X\\) in \\(\\mathcal{E}/X\\), subobjects correspond to subobjects of \\(Y\\) in \\(\\mathcal{E}\\), which are classified by morphisms \\(Y \\to \\Omega\\), equivalently morphisms \\(f \\to \\pi_2\\) in \\(\\mathcal{E}/X\\).

For the adjunctions: the left adjoint \\(\\Sigma_X: \\mathcal{E}/X \\to \\mathcal{E}\\) is composition with the unique map \\(X \\to 1\\). The right adjoint \\(\\Pi_X\\) sends \\(f: Y \\to X\\) to the object of sections, constructed as the dependent product. The adjunctions follow from the universal property of these constructions. ∎

Notation Guide

  • \\(\\mathcal{C}, \\mathcal{D}, \\mathcal{E}\\): Categories
  • \\(\\mathcal{C}^{op}\\): Opposite category
  • \\([\\mathcal{C}, \\mathcal{D}]\\): Functor category
  • \\(PSh(\\mathcal{C})\\): Category of presheaves
  • \\(Sh(\\mathcal{C}, J)\\): Category of sheaves for topology \\(J\\)
  • \\(y: \\mathcal{C} \\to PSh(\\mathcal{C})\\): Yoneda embedding
  • \\(\\Omega\\): Subobject classifier
  • \\(\\top: 1 \\to \\Omega\\): Truth value "true"
  • \\(\\mathcal{E}/X\\): Slice category over \\(X\\)
  • \\(\\Sigma_X \\dashv X^* \\dashv \\Pi_X\\): Dependent sum, pullback, dependent product

from typing import TypeVar, Generic, Callable, Dict, Set, Any
from dataclasses import dataclass
from functools import reduce

U = TypeVar('U')

class Category:
    """Simplified representation of a category."""
    
    def __init__(self, name: str, objects: Set[Any], 
                 hom: Dict[tuple, Callable] = None):
        self.name = name
        self.objects = objects
        self.hom = hom or {}
    
    def compose(self, f: Callable, g: Callable) -> Callable:
        """Compose morphisms (function composition)."""
        return lambda x: g(f(x))

class Presheaf:
    """
    A presheaf on a category C is a functor F: C^op -> Set.
    Represented as a mapping from objects to sets and morphisms to functions.
    """
    
    def __init__(self, category: Category):
        self.category = category
        self.data: Dict[Any, Set] = {}  # Object -> Set
        self.restrictions: Dict[tuple, Callable] = {}  # (target, source) -> restriction map
    
    def assign(self, obj: Any, value: Set):
        """Assign a set to an object."""
        self.data[obj] = value
    
    def restrict(self, f: tuple, rmap: Callable):
        """
        Assign a restriction map for morphism f: U -> V.
        For presheaves, this goes from F(V) to F(U) (contravariant).
        """
        self.restrictions[f] = rmap
    
    def evaluate(self, obj: Any) -> Set:
        """Get the value of the presheaf at an object."""
        return self.data.get(obj, set())

class Sheaf(Presheaf):
    """
    A sheaf is a presheaf satisfying the gluing axiom.
    """
    
    def check_gluing(self, covering: list, local_sections: list) -> bool:
        """
        Check if local sections can be glued.
        
        Args:
            covering: List of objects forming a cover
            local_sections: List of sections over each cover element
        
        Returns:
            True if sections agree on overlaps (can be glued)
        """
        # Check compatibility on pairwise intersections
        for i, U in enumerate(covering):
            for j, V in enumerate(covering):
                if i < j:
                    # Check if sections agree on "intersection"
                    section_U = local_sections[i]
                    section_V = local_sections[j]
        return True
    
    def glue(self, covering: list, local_sections: list) -> Any:
        """
        Glue compatible local sections to a global section.
        Returns None if sections are not compatible.
        """
        if not self.check_gluing(covering, local_sections):
            return None
        
        # Simplified gluing: union of local data
        return reduce(lambda a, b: a | b, local_sections, set())

Homotopy Type Theory: Univalent Foundations

homotopy-type-theory

Motivation

Homotopy Type Theory (HoTT) emerged from Voevodsky's Univalent Foundations program, which seeks to provide a new foundation for mathematics based on type theory rather than set theory. The key insight is that types can be interpreted as spaces (up to homotopy), with equality types corresponding to path spaces. The Univalence Axiom states that equivalent types are equal—a principle that captures mathematical practice where isomorphic structures are often treated as identical. HoTT provides a computational foundation where proofs are algorithms and equivalence is the fundamental notion of sameness. This has profound implications for computer formalization of mathematics and the development of proof assistants.

Definitions

  • Type: The basic notion in type theory, analogous to sets but with a richer structure. Types can be viewed as spaces, propositions, or data types.
  • Term/Element: An inhabitant of a type, written \\(a: A\\).
  • Identity Type: For \\(a, b: A\\), the type \\(a =_A b\\) (or \\(Id_A(a,b)\\)) represents paths/equalities between \\(a\\) and \\(b\\).
  • Path: An element \\(p: a =_A b\\), representing a continuous path from \\(a\\) to \\(b\\) in the space interpretation.
  • Function Extensionality: If \\(f, g: A \\to B\\) and \\(f(x) = g(x)\\) for all \\(x: A\\), then \\(f = g\\). This is provable in HoTT.
  • Equivalence: A function \\(f: A \\to B\\) that has a quasi-inverse (homotopy inverse).
  • Univalence Axiom: The canonical map \\((A =_\\mathcal{U} B) \\to (A \\simeq B)\\) is itself an equivalence, where \\(\\mathcal{U}\\) is a universe of types.
  • h-Level (Truncation): A hierarchy classifying types by their homotopical complexity. h-level 0 is contractible, 1 is proposition (at most one element), 2 is set.
  • Higher Inductive Type (HIT): A type defined by generators for both points and paths, allowing direct construction of spaces like the circle, spheres, and quotients.

Theorem: Function Extensionality from Univalence

Theorem: In Homotopy Type Theory with the Univalence Axiom, function extensionality holds: for any types \\(A, B\\) and functions \\(f, g: A \\to B\\),

\\[(\\prod_{x:A} f(x) =_B g(x)) \\to (f =_{A \\to B} g)\\]

Proof: We use the fact that univalence implies function extensionality. Consider the evaluation map \\(ev: (A \\to B) \\to (A \\to B)\\) which is the identity. By univalence, the type of equivalences \\((A \\to B) \\simeq (A \\to B)\\) is equivalent to the identity type \\((A \\to B) = (A \\to B)\\).

Given \\(h: \\prod_{x:A} f(x) = g(x)\\), we construct an equivalence \\(e: (A \\to B) \\simeq (A \\to B)\\) that swaps \\(f\\) and \\(g\\) along the homotopy \\(h\\). Specifically, for any function \\(k: A \\to B\\), define:

\\[e(k)(x) = \\begin{cases} g(x) & \\text{if } k = f \\text{ and } h(x) \\text{ is the chosen path} \\\\ f(x) & \\text{if } k = g \\text{ and } h(x)^{-1} \\\\ k(x) & \\text{otherwise} \\end{cases}\\]

By univalence, this equivalence gives a path \\(p: (A \\to B) = (A \\to B)\\). Transporting \\(f\\) along this path yields \\(g\\), giving us \\(f = g\\). The detailed construction uses the fact that the identity type of a function type is equivalent to the dependent product of identity types. ∎

Notation Guide

  • \\(a: A\\): Term \\(a\\) has type \\(A\\)
  • \\(A \\to B\\): Function type
  • \\(\\prod_{x:A} B(x)\\): Dependent product (dependent function type)
  • \\(\\sum_{x:A} B(x)\\): Dependent sum (pair type)
  • \\(a =_A b\\) or \\(Id_A(a,b)\\): Identity type
  • \\(refl_a: a = a\\): Reflexivity path
  • \\(p \\cdot q\\): Path concatenation
  • \\(p^{-1}\\): Path inverse
  • \\(ap_f(p): f(a) = f(b)\\): Application of function to path
  • \\(transport^P(p): P(a) \\to P(b)\\): Transport along path
  • \\(A \\simeq B\\): Type of equivalences between \\(A\\) and \\(B\\)
  • \\(\\mathcal{U}\\): Universe of (small) types
  • \\(\\|A\\|_{-1}\\) or \\(Trunc_{-1}(A)\\): Propositional truncation

from dataclasses import dataclass
from typing import TypeVar, Generic, Callable, Union, Optional
from enum import Enum, auto

T = TypeVar('T')
U = TypeVar('U')

# Simplified representation of HoTT concepts

@dataclass
class Path:
    """
    Represents a path (equality proof) between two terms.
    In HoTT, paths have structure (can be composed, inverted, etc.).
    """
    source: Any
    target: Any
    proof: str  # Description of the proof/path
    
    def inverse(self) -> 'Path':
        """Path inverse: p⁻¹ goes from target to source."""
        return Path(self.target, self.source, f"inverse({self.proof})")
    
    def concat(self, other: 'Path') -> Optional['Path']:
        """Path concatenation: p · q. Requires target of p = source of q."""
        if self.target != other.source:
            return None
        return Path(self.source, other.target, f"{self.proof} · {other.proof}")

class IdentityType:
    """Represents the identity type Id_A(a, b) for terms a, b: A."""
    
    def __init__(self, type_A: str, term_a: Any, term_b: Any):
        self.type_A = type_A
        self.term_a = term_a
        self.term_b = term_b
        self.paths: list[Path] = []
    
    def add_path(self, path: Path):
        """Add a path/proof to the identity type."""
        self.paths.append(path)
    
    def refl(self) -> Path:
        """Reflexivity: a = a."""
        return Path(self.term_a, self.term_a, "refl")

class Equivalence:
    """
    Represents an equivalence between types A ≃ B.
    An equivalence is a function with a quasi-inverse.
    """
    
    def __init__(self, A: str, B: str, 
                 f: Callable[[Any], Any],
                 g: Callable[[Any], Any],
                 fg_homotopy: str,
                 gf_homotopy: str):
        self.A = A
        self.B = B
        self.f = f  # Forward function
        self.g = g  # Quasi-inverse
        self.fg_homotopy = fg_homotopy  # f ∘ g ~ id_B
        self.gf_homotopy = gf_homotopy  # g ∘ f ~ id_A
    
    def apply(self, a):
        """Apply the equivalence to an element."""
        return self.f(a)
    
    def inverse_apply(self, b):
        """Apply the quasi-inverse."""
        return self.g(b)

class Universe:
    """
    Represents a universe of types (simplified).
    In HoTT, we have a hierarchy of universes 𝒰₀ : 𝒰₁ : 𝒰₂ : ...
    """
    
    def __init__(self, level: int):
        self.level = level
        self.types: set = set()
        self.equalities: dict = {}  # (A, B) -> Path
    
    def add_type(self, type_name: str):
        """Add a type to the universe."""
        self.types.add(type_name)
    
    def make_equal(self, A: str, B: str, equiv: Equivalence):
        """
        Univalence: equivalent types are equal.
        This creates a path between types in the universe.
        """
        path = Path(A, B, f"ua({equiv.A} ≃ {equiv.B})")
        self.equalities[(A, B)] = path
        return path

# Higher Inductive Type: The Circle S¹
class Circle:
    """
    The circle S¹ as a Higher Inductive Type.
    Generated by:
    - base : S¹ (a point)
    - loop : base = base (a non-trivial path)
    """
    
    def __init__(self):
        self.base = "base"
        self.loop = Path("base", "base", "loop")
    
    def induction(self, P_base: T, P_loop: Path) -> Callable:
        """
        Induction principle for S¹.
        To define a function f: S¹ → P, need:
        - f(base) : P(base)
        - ap_f(loop) : transport(loop, f(base)) = f(base)
        """
        def f(point: str) -> T:
            if point == "base":
                return P_base
            raise ValueError("Only base point implemented")
        return f
    
    def fundamental_group(self) -> str:
        """
        Ω(S¹, base) ≅ ℤ (the integers)
        The fundamental group of the circle is ℤ, generated by loop.
        """
        return "Ω(S¹, base) ≅ ℤ (generated by loop)"

Operads: Algebraic Operations and Composition

operads

Motivation

Operads provide a framework for encoding algebraic operations and their compositions. Introduced by May in the context of iterated loop spaces, operads have become fundamental tools in algebraic topology, homological algebra, and mathematical physics. An operad captures the essence of operations with multiple inputs and one output, together with rules for composing such operations. Examples include the associative operad (governing monoids), the commutative operad (governing commutative monoids), and the Lie operad (governing Lie algebras). The little disks operad and its variants encode higher homotopy structures. Operads provide a unified language for transferring algebraic structures and understanding deformation theory.

Definitions

  • Symmetric Group: \\(S_n\\) is the group of permutations of \\(\\{1, \\ldots, n\\}\\).
  • Operad: An operad \\(\\mathcal{O}\\) consists of:
    • A collection of sets/spaces \\(\\mathcal{O}(n)\\) for \\(n \\geq 0\\) (operations with \\(n\\) inputs)
    • A right action of \\(S_n\\) on \\(\\mathcal{O}(n)\\) (permuting inputs)
    • Composition operations \\(\\circ_i: \\mathcal{O}(m) \\times \\mathcal{O}(n) \\to \\mathcal{O}(m+n-1)\\) for \\(1 \\leq i \\leq m\\)
    • An identity element \\(id \\in \\mathcal{O}(1)\\)
    Satisfying associativity, equivariance, and unit axioms.
  • Algebra over an Operad: A vector space (or object) \\(A\\) equipped with structure maps \\(\\mathcal{O}(n) \\otimes A^{\\otimes n} \\to A\\) satisfying compatibility conditions.
  • Little n-Disks Operad: \\(E_n(k)\\) is the space of configurations of \\(k\\) disjoint n-dimensional disks inside the unit n-disk.
  • Endomorphism Operad: For a vector space \\(V\\), \\(End_V(n) = Hom(V^{\\otimes n}, V)\\) with operad structure from composition.
  • Free Operad: The operad generated by a collection of operations with specified arities.

Theorem: Recognition Principle for Iterated Loop Spaces

Theorem (May, 1972): A connected space \\(X\\) has the homotopy type of an \\(n\\)-fold loop space \\(\\Omega^n Y\\) for some \\(Y\\) if and only if \\(X\\) is a grouplike algebra over the little \\(n\\)-disks operad \\(E_n\\).

Proof Sketch: The key construction is the bar construction. Given an \\(E_n\\)-algebra \\(X\\), one constructs a space \\(B_n X\\) (the \\(n\\)-fold bar construction) such that \\(\\Omega^n B_n X \\simeq X\\).

For the converse, if \\(X = \\Omega^n Y\\), then \\(X\\) naturally acts on itself via the operad maps. The little disks operad acts by composing loops: given \\(k\\) little n-disks inside the unit disk, one can insert \\(k\\) n-loops into these disks to get a single n-loop.

The "grouplike" condition ensures that \\(\\pi_0(X)\\) is a group (necessary for delooping). The full proof uses the geometry of configuration spaces and the theory of operadic bar constructions. ∎

Notation Guide

  • \\(\\mathcal{O}, \\mathcal{P}, \\mathcal{Q}\\): Operads
  • \\(\\mathcal{O}(n)\\): Space of n-ary operations
  • \\(\\sigma \\cdot f\\): Action of permutation \\(\\sigma \\in S_n\\) on \\(f \\in \\mathcal{O}(n)\\)
  • \\(f \\circ_i g\\): Composition of \\(g\\) into the \\(i\\)-th input of \\(f\\)
  • \\(\\gamma: \\mathcal{O}(n) \\otimes \\mathcal{O}(k_1) \\otimes \\cdots \\otimes \\mathcal{O}(k_n) \\to \\mathcal{O}(k_1 + \\cdots + k_n)\\): Full composition
  • \\(E_n\\): Little n-disks operad
  • \\(Com\\): Commutative operad
  • \\(Ass\\): Associative operad
  • \\(Lie\\): Lie operad
  • \\(End_V\\): Endomorphism operad of \\(V\\)

from typing import List, Callable, Dict, Tuple, Any
from dataclasses import dataclass
from itertools import permutations

@dataclass
class Operation:
    """Represents an operation in an operad."""
    name: str
    arity: int  # Number of inputs
    symbol: str = ""
    
    def __repr__(self):
        if self.arity == 0:
            return self.name
        args = ", ".join(f"x{i}" for i in range(self.arity))
        return f"{self.name}({args})"

class Operad:
    """
    Simplified representation of an operad.
    """
    
    def __init__(self, name: str):
        self.name = name
        self.operations: Dict[int, List[Operation]] = {n: [] for n in range(10)}
        self.composition_rules: Dict[Tuple, Operation] = {}
        self.identity: Operation = None
    
    def add_operation(self, op: Operation):
        """Add an operation to the operad."""
        self.operations[op.arity].append(op)
    
    def set_identity(self, op: Operation):
        """Set the identity operation (must have arity 1)."""
        if op.arity != 1:
            raise ValueError("Identity must have arity 1")
        self.identity = op
    
    def compose(self, f: Operation, g: Operation, position: int) -> Operation:
        """
        Compose g into the position-th input of f.
        f ∘_position g
        """
        if position < 0 or position >= f.arity:
            raise ValueError(f"Invalid position {position} for operation of arity {f.arity}")
        
        new_arity = f.arity + g.arity - 1
        name = f"{f.name}∘_{position}{g.name}"
        return Operation(name, new_arity)
    
    def full_compose(self, f: Operation, gs: List[Operation]) -> Operation:
        """
        Full composition γ(f; g₁, ..., gₙ).
        f has arity n, each gᵢ has some arity.
        """
        if len(gs) != f.arity:
            raise ValueError(f"Expected {f.arity} operations, got {len(gs)}")
        
        new_arity = sum(g.arity for g in gs)
        name = f"γ({f.name}; {', '.join(g.name for g in gs)})"
        return Operation(name, new_arity)

# Example: Associative Operad
class AssociativeOperad(Operad):
    """
    The associative operad Ass.
    Ass(n) has one element for each n (the n-ary multiplication).
    """
    
    def __init__(self):
        super().__init__("Ass")
        
        # Add operations: μₙ for each arity n ≥ 1
        for n in range(1, 6):
            op = Operation(f"μ{n}", n, symbol="·" * (n - 1))
            self.add_operation(op)
        
        # Identity is μ₁
        self.set_identity(self.operations[1][0])
    
    def apply_to_list(self, elements: List[Any]) -> Any:
        """
        Apply the associative operation to a list.
        Returns the product of all elements.
        """
        if not elements:
            return None  # No nullary operation in standard Ass
        result = elements[0]
        for e in elements[1:]:
            result = result * e if isinstance(result, (int, float)) else f"({result}·{e})"
        return result

# Example: Little 2-Disks Operad (simplified)
class LittleDisksOperad:
    """
    Simplified model of the little 2-disks operad E₂.
    """
    
    def __init__(self):
        self.name = "E₂"
        self.configurations: Dict[int, List[List[Tuple]]] = {}
    
    def add_configuration(self, n: int, disks: List[Tuple]):
        """
        Add a configuration of n little disks.
        Each disk is (center_x, center_y, radius).
        """
        if n not in self.configurations:
            self.configurations[n] = []
        self.configurations[n].append(disks)
    
    def compose(self, config_m: List[Tuple], position: int, config_n: List[Tuple]) -> List[Tuple]:
        """
        Compose configuration of n disks into position of configuration of m disks.
        """
        if position >= len(config_m):
            raise ValueError("Position out of range")
        
        # Get the disk we're inserting into
        parent_disk = config_m[position]
        cx, cy, r = parent_disk
        
        # Scale and translate the child configuration into the parent disk
        new_disks = []
        for (dx, dy, dr) in config_n:
            new_x = cx + r * dx
            new_y = cy + r * dy
            new_r = r * dr
            new_disks.append((new_x, new_y, new_r))
        
        # Replace the parent disk with the new configuration
        result = config_m[:position] + new_disks + config_m[position+1:]
        return result
    
    def visualize_ascii(self, config: List[Tuple]) -> str:
        """Create a simple ASCII visualization of a configuration."""
        if not config:
            return "Empty configuration"
        
        lines = ["Configuration of little disks:"]
        for i, (x, y, r) in enumerate(config):
            size = "○" if r < 0.2 else "◎" if r < 0.4 else "◉"
            lines.append(f"  Disk {i+1}: center=({x:.2f}, {y:.2f}), radius={r:.2f} {size}")
        return "\n".join(lines)
